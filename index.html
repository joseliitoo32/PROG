UD 4

Clases y Objetos

La POO es un paradigma de programación que trata de modelar de manera abstracta el mundo real. Una clase es una plantilla que define propiedades (atributos) y comportamientos (métodos). Un objeto es una instancia concreta de esa clase.

4.1 Concepto de Clase

Una clase actúa como un tipo de dato personalizado que combina datos y código. Sus elementos principales son los atributos (el estado) y los métodos (el comportamiento). El nombre de una clase sigue la convención UpperCamelCase.

ElementoDescripciónConvención de nombre
AtributoVariable que almacena el estado del objetolowerCamelCase (sustantivo)
MétodoFunción que define el comportamientolowerCamelCase (verbo)
ClasePlantilla que define el tipoUpperCamelCase
ConstructorMétodo especial para crear objetosMismo nombre que la clase
Persona.java 
public class Persona {
    // Atributos (estado del objeto)
    private String nombre;
    private int    edad;
    private double estatura;

    // Método (comportamiento)
    public void cumplirAnios() {
        edad++;
    }

    public void crecer(double incremento) {
        estatura += incremento;
    }
}

4.2 Atributos

Los atributos almacenan el estado de una clase. Se declaran al principio de la clase y no es obligatorio inicializarlos (Java los inicializa a sus valores por defecto). La visibilidad recomendada es private.

TipoValor por defectoEjemplo
int, byte, short, long0private int edad;
float, double0.0private double saldo;
booleanfalseprivate boolean activo;
char'\u0000'private char inicial;
Objeto (String, etc.)nullprivate String nombre;

La sintaxis completa de declaración de un atributo es:

Atributos.java 
// [visibilidad] [static] [final] tipo nombre [= valorInicial];

private        String  nombre;          // atributo de instancia
private static int     totalObjetos = 0; // atributo de clase (compartido)
public  static final double PI = 3.14159; // constante de clase

4.3 Métodos

Los métodos son funciones definidas dentro de una clase. Sus nombres suelen contener un verbo. La sintaxis de declaración es: [visibilidad] [static] tipoRetorno nombreMétodo(parámetros).

Calculadora.java 
public class Calculadora {

    // Método que devuelve un valor
    public static int sumar(int a, int b) {
        return a + b;
    }

    // Procedimiento (no devuelve nada)
    public static void imprimirResultado(int resultado) {
        System.out.println("Resultado: " + resultado);
    }

    public static void main(String[] args) {
        int res = sumar(5, 10); // res = 15
        imprimirResultado(res);
    }
}

4.4 Constructores

Los constructores son métodos especiales que se invocan al crear un objeto con new. Tienen el mismo nombre que la clase y no tienen tipo de retorno. Si no se declara ninguno, Java proporciona un constructor por defecto (sin parámetros). En el momento en que se declara alguno, el constructor por defecto desaparece.

Tipo de constructorDescripción
Por defectoProporcionado por Java si no se declara ninguno. Inicializa atributos a sus valores por defecto.
Sin parámetrosDeclarado explícitamente sin parámetros. Permite inicializar con valores predefinidos.
Con parámetrosRecibe valores para inicializar los atributos en la creación del objeto.
Persona.java 
public class Persona {
    private String nombre;
    private int    edad;
    private double estatura;

    // Constructor sin parámetros
    public Persona() {
        nombre   = "anónimo";
        edad     = 18;
        estatura = 1.70;
    }

    // Constructor con todos los parámetros
    public Persona(String nombre, int edad, double estatura) {
        this.nombre   = nombre;
        this.edad     = edad;
        this.estatura = estatura;
    }

    // Constructor con nombre únicamente (reutiliza el anterior con this())
    public Persona(String nombre) {
        this(nombre, 18, 1.70); // this() debe ir al principio
    }
}

// Uso en otra clase:
Persona p1 = new Persona();
Persona p2 = new Persona("Ana", 25, 1.65);
Persona p3 = new Persona("Luis");

4.5 Referencia this y Ámbito de Variables

La palabra reservada this hace referencia al propio objeto. Se usa principalmente para distinguir entre atributos de la clase y variables locales con el mismo nombre, y para invocar otros constructores con this().

UsoThis.java 
public class Persona {
    private String nombre; // atributo de clase

    public void setNombre(String nombre) { // parámetro local
        this.nombre = nombre; // this.nombre → atributo; nombre → parámetro
    }
}

4.6 Referencias, Operador . y null

Los objetos en Java se acceden mediante referencias (punteros a memoria), igual que los arrays. Para acceder a los miembros de un objeto se usa el operador punto .. Si una variable de tipo objeto no apunta a ningún objeto, su valor es null; intentar usar un objeto nulo produce una NullPointerException.

Referencias.java 
Persona p1 = new Persona("Ana", 20, 1.65);
Persona p2 = p1; // p2 apunta al MISMO objeto que p1

p2.setNombre("Lucía");
System.out.println(p1.getNombre()); // Imprime: Lucía (mismo objeto)

Persona p3 = null;
// p3.getNombre(); → NullPointerException !

4.7 Enumerados (enum)

Los enumerados son tipos de dato especiales que limitan los valores posibles a un conjunto predefinido de constantes. Son útiles para representar categorías fijas como días de la semana, estados o géneros.

Sexo.java 
public enum Sexo {
    HOMBRE, MUJER, NO_BINARIO
}

// Uso en la clase Persona:
private Sexo sexo;

Persona p = new Persona();
p.setSexo(Sexo.MUJER);
System.out.println(p.getSexo()); // MUJER
UD 5

Principios de la POO

La Programación Orientada a Objetos se basa en cuatro pilares fundamentales: Encapsulación, Herencia, Polimorfismo y Abstracción. Esta unidad profundiza en cada uno de ellos aplicados a Java.

5.1 Encapsulación y Visibilidad

La encapsulación consiste en ocultar los datos internos de una clase y controlar el acceso mediante métodos. Esto protege el estado del objeto y evita usos incorrectos. Los atributos se declaran private y se accede a ellos mediante métodos getter (lectura) y setter (escritura).

ModificadorMisma claseMismo paqueteSubclaseCualquier clase
private✅❌❌❌
package (defecto)✅✅❌❌
protected✅✅✅❌
public✅✅✅✅
CuentaBancaria.java 
public class CuentaBancaria {
    private String titular;
    private double saldo;

    // Getter
    public String getTitular() { return titular; }
    public double getSaldo()   { return saldo; }

    // Setter con validación
    public void ingresar(double cantidad) {
        if (cantidad > 0) saldo += cantidad;
    }

    public void retirar(double cantidad) {
        if (cantidad > 0 && cantidad <= saldo) saldo -= cantidad;
    }
}

5.2 Atributos y Métodos Estáticos (static)

Los miembros estáticos pertenecen a la clase, no a los objetos. Son compartidos por todas las instancias. Los métodos estáticos no necesitan un objeto para ejecutarse, pero no pueden acceder directamente a miembros no estáticos. El método main es estático porque la JVM lo invoca sin crear ningún objeto.

ContadorObjetos.java 
public class ContadorObjetos {
    private static int totalObjetos = 0; // atributo de clase
    private String nombre;

    public ContadorObjetos(String nombre) {
        this.nombre = nombre;
        totalObjetos++; // se incrementa con cada new
    }

    public static void mostrarTotal() {
        System.out.println("Total objetos: " + totalObjetos);
    }
}

// Uso:
new ContadorObjetos("A");
new ContadorObjetos("B");
ContadorObjetos.mostrarTotal(); // Total objetos: 2

5.3 Paquetes y Librerías

Los paquetes organizan las clases en namespaces jerárquicos (como carpetas). Para usar una clase de otro paquete se importa con import. Una librería (o biblioteca) es código ya desarrollado que se reutiliza para no reinventar la rueda. En Java, las librerías se distribuyen como archivos .jar.

Main.java 
package app;                    // declara el paquete
import modelo.Persona;          // importa una clase
import java.util.*;             // importa todo el paquete java.util

// java.lang se importa automáticamente (String, Math, System, etc.)
public class Main {
    public static void main(String[] args) {
        Persona p = new Persona("Ana");
        System.out.println(p);
    }
}

5.4 Herencia

La herencia permite crear una clase nueva a partir de otra existente, reutilizando su código y ampliándolo. La relación es de tipo "es un" (p. ej., Alumno es una Persona). En Java se usa la palabra clave extends. No existe herencia múltiple en Java (una clase solo puede extender una), pero sí herencia transitiva. Todos los miembros de la superclase (excepto constructores) son heredados por la subclase.

Herencia.java 
public class Animal {
    protected String nombre;

    public Animal(String nombre) {
        this.nombre = nombre;
    }

    public void dormir() {
        System.out.println(nombre + " está durmiendo.");
    }
}

public class Perro extends Animal {

    public Perro(String nombre) {
        super(nombre); // invoca al constructor del padre
    }

    // Sobreescritura con @Override
    @Override
    public void dormir() {
        super.dormir();  // reutiliza el método del padre
        System.out.println("(ronca)");
    }

    public void ladrar() {
        System.out.println("¡Guau!");
    }
}

5.5 Polimorfismo

El polimorfismo permite que una misma referencia se comporte de distintas formas según el objeto concreto al que apunte. Una variable de tipo clase padre puede referenciar objetos de clases hijas. El método que se ejecuta se decide en tiempo de ejecución, no en compilación.

Polimorfismo.java 
Animal a1 = new Perro("Rex");
Animal a2 = new Gato("Misi");

// Aunque a1 y a2 son de tipo Animal,
// Java ejecuta el método del tipo REAL del objeto
a1.hacerSonido(); // → Guau!
a2.hacerSonido(); // → Miau!

// Array polimórfico
Animal[] animales = { new Perro("Rex"), new Gato("Misi") };
for (Animal a : animales) {
    a.hacerSonido(); // comportamiento según tipo real
}

5.6 La Clase Object

Object es la superclase base de todas las clases en Java. Toda clase hereda implícitamente de ella. Proporciona métodos esenciales que conviene sobrescribir en clases propias.

MétodoDescripción¿Sobrescribir?
toString()Representación textual del objetoSí, siempre
equals(Object obj)Compara contenido (no referencia)Sí, si se necesita comparar por valor
hashCode()Código hash del objetoSí, junto con equals()
getClass()Devuelve la clase del objetoNo
PersonaConObject.java 
public class Persona {
    private String nombre;
    private int    edad;

    @Override
    public String toString() {
        return "Persona: " + nombre + ", Edad: " + edad;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof Persona)) return false;
        Persona otra = (Persona) obj;
        return edad == otra.edad && nombre.equals(otra.nombre);
    }
}

// Uso:
Persona p = new Persona("Fran", 30);
System.out.println(p);             // Persona: Fran, Edad: 30
System.out.println("Info: " + p); // toString() implícito

5.7 Clases y Métodos Abstractos

Una clase abstracta no puede ser instanciada directamente; sirve como base para otras clases. Un método abstracto se declara sin implementación y obliga a las subclases concretas a implementarlo. Si una clase tiene al menos un método abstracto, debe ser declarada abstracta.

Abstracto.java 
abstract class Figura {
    // Método abstracto: sin cuerpo, termina en ;
    public abstract double calcularArea();

    // Método concreto (con implementación)
    public void mostrarTipo() {
        System.out.println("Soy una figura geométrica.");
    }
}

class Circulo extends Figura {
    private double radio;

    public Circulo(double radio) { this.radio = radio; }

    @Override
    public double calcularArea() {
        return Math.PI * radio * radio;
    }
}

// Figura f = new Figura(); → ERROR: no se puede instanciar
Figura f = new Circulo(5.0); // polimorfismo
System.out.println(f.calcularArea());

5.8 Modificador final

El modificador final tiene diferentes efectos según donde se aplique: en una variable impide reasignarla (constante); en un método impide que sea sobrescrito; en una clase impide que sea extendida.

Final.java 
// Variable final → constante
final double PI = 3.14159;
// PI = 3.0; → ERROR de compilación

// Método final → no puede sobrescribirse
public final void display() {
    System.out.println("Método final.");
}

// Clase final → no puede heredarse (ej: String, Math)
public final class MiClaseFinal { ... }

// OJO: final en objeto → no se puede reasignar la referencia,
// pero SÍ modificar el contenido del objeto
final Persona p = new Persona("Paco");
p.setNombre("Fran");   // ✅ permitido
// p = new Persona("Luis"); → ERROR

5.9 Paso por Valor y por Referencia

En Java siempre se pasa por valor, pero el significado varía según el tipo. Para tipos primitivos se pasa una copia del dato (los cambios no afectan al original). Para objetos se pasa una copia de la referencia, por lo que las modificaciones sobre el objeto sí afectan al original.

PasoPorValor.java 
public static void modificarPrimitivo(int numero) {
    numero = 20; // solo cambia la copia local
}

public static void modificarObjeto(StringBuilder texto) {
    texto.append(" modificado"); // modifica el objeto original
}

public static void main(String[] args) {
    int n = 5;
    modificarPrimitivo(n);
    System.out.println(n); // 5 (no cambió)

    StringBuilder sb = new StringBuilder("Hola");
    modificarObjeto(sb);
    System.out.println(sb); // Hola modificado (sí cambió)
}
UD 6

Interfaces

Una interfaz es una plantilla que define un conjunto de métodos abstractos y constantes sin implementación. Representa un contrato que las clases que la implementan deben cumplir. Permite la herencia múltiple de tipo y favorece el polimorfismo.

6.1 Definición y Sintaxis

Las interfaces se declaran con la palabra clave interface. Sus métodos son implícitamente public abstract y sus atributos son implícitamente public static final. Desde Java 8, las interfaces pueden tener métodos default (con implementación) y métodos static.

Vehiculo.java 
public interface Vehiculo {
    // Constante (implícitamente public static final)
    int VELOCIDAD_MAXIMA = 120;

    // Métodos abstractos (implícitamente public abstract)
    void acelerar(int cantidad);
    void frenar(int cantidad);

    // Método default (Java 8+): tiene implementación
    default void mostrarVelocidadMaxima() {
        System.out.println("Velocidad máxima: " + VELOCIDAD_MAXIMA);
    }

    // Método estático (Java 8+)
    static void informacionGeneral() {
        System.out.println("Los vehículos permiten desplazarse.");
    }
}

6.2 Implementación de Interfaces

Una clase implementa una interfaz con la palabra clave implements. Puede implementar múltiples interfaces a la vez (herencia múltiple de tipo). Debe proporcionar implementación para todos los métodos abstractos de la interfaz.

Coche.java 
public class Coche implements Vehiculo {
    private int velocidadActual = 0;

    @Override
    public void acelerar(int cantidad) {
        velocidadActual = Math.min(velocidadActual + cantidad, VELOCIDAD_MAXIMA);
    }

    @Override
    public void frenar(int cantidad) {
        velocidadActual = Math.max(velocidadActual - cantidad, 0);
    }
}

// Herencia + interfaces a la vez:
class Perro extends Animal implements Corredor, Nadador { ... }

// Buena práctica: declarar con la interfaz, instanciar con la clase
Vehiculo v = new Coche(); // polimorfismo
v.acelerar(50);
v.mostrarVelocidadMaxima();
Vehiculo.informacionGeneral();

UD 7

Excepciones

Una excepción es un evento producido durante la ejecución de un programa que altera el flujo normal de ejecución. Java proporciona un mecanismo estructurado para detectar, manejar y propagar estos errores.

7.1 Jerarquía de Excepciones

Todas las excepciones heredan de Throwable. Se dividen en dos grandes grupos: Error (irrecuperables, de la JVM) y Exception (recuperables, del código). Las Exception se subdividen a su vez en checked (verificadas) y unchecked (no verificadas).

TipoDescripción¿Obligatorio gestionar?Ejemplos
ErrorErrores graves de la JVM, irrecuperablesNoStackOverflowError, OutOfMemoryError
RuntimeException (Unchecked)Errores de programación. Java los lanza automáticamente.No (pero se puede)NullPointerException, ArrayIndexOutOfBoundsException, IllegalArgumentException
Exception (Checked)Situaciones previsibles que dependen del uso del programaSí (capturar o propagar)IOException, FileNotFoundException, SQLException, ParseException

7.2 Captura: try – catch – finally

El bloque try contiene el código que puede lanzar excepciones. El bloque catch captura y gestiona una excepción específica. El bloque finally se ejecuta siempre, independientemente de si se produjo o no una excepción (ideal para liberar recursos).

TryCatch.java 
public static void main(String[] args) {
    int a = 0, b = 300;

    try {
        int resultado = b / a; // lanza ArithmeticException
        System.out.println("Resultado: " + resultado);

    } catch (ArithmeticException e) {
        System.out.println("Error: " + e.getMessage()); // / by zero
        e.printStackTrace(); // traza completa del error

    } catch (Exception e) {
        System.out.println("Error genérico: " + e.getMessage());

    } finally {
        System.out.println("Programa finalizado."); // siempre se ejecuta
    }
}

7.3 Propagación (throws) y Lanzamiento (throw)

throws en la firma del método indica que ese método puede lanzar una excepción y delega su gestión al código que lo invoca. throw lanza explícitamente una excepción dentro del código.

Propagacion.java 
// throws → propaga la excepción al llamador
public static double division(double a, double b)
        throws ArithmeticException {
    if (b == 0)
        throw new ArithmeticException("Divisor no puede ser cero");
    return a / b;
}

public static void main(String[] args) {
    try {
        System.out.println(division(10, 0));
    } catch (ArithmeticException e) {
        System.out.println("Capturada: " + e.getMessage());
    }
}

// Relanzar una excepción:
try { ... }
catch (IOException ex) {
    // tratamiento intermedio...
    throw ex; // se sigue propagando
}

7.4 Excepciones Personalizadas

Se pueden crear excepciones propias extendiendo de la clase de excepción adecuada. Si extiende de RuntimeException será unchecked; si extiende de Exception será checked.

NumeroRepetido.java 
// 1. Crear la clase de excepción personalizada
public class NumeroRepetido extends IllegalArgumentException {
    public NumeroRepetido(String mensaje) {
        super(mensaje); // reutiliza el constructor del padre
    }
}

// 2. Lanzarla cuando sea necesario
public static void agregarNumero(List<Integer> lista, int num)
        throws NumeroRepetido {
    if (lista.contains(num))
        throw new NumeroRepetido("El número " + num + " ya existe.");
    lista.add(num);
}

// 3. Capturarla
try {
    agregarNumero(lista, 5);
} catch (NumeroRepetido e) {
    System.out.println(e.getMessage());
    e.printStackTrace();
}

7.5 Aserciones

Las aserciones (assert) se usan para depurar el código durante el desarrollo. No deben usarse en producción. Se activan con el argumento -ea al ejecutar la JVM.

Aserciones.java 
int x = -15;
// Si x no es positivo, lanza AssertionError con el mensaje
assert x > 0 : "El valor debe ser positivo";
System.out.println("Valor: " + x);

// Ejecutar con: java -ea MiClase
UD 8

Tipos Abstractos de Datos y Colecciones (JCF)

El Java Collections Framework (JCF) es un conjunto de interfaces y clases del paquete java.util que proporciona estructuras de datos reutilizables: listas, conjuntos, mapas, etc. Los tipos genéricos permiten indicar el tipo de elemento que manejará la colección, aportando seguridad de tipos en tiempo de compilación.

8.1 Tipos Genéricos y Tipos Envoltorio (Wrappers)

Las colecciones no admiten tipos primitivos, por lo que se usan los tipos envoltorio (Integer, Double, etc.). Java realiza autoboxing (primitivo → objeto) y unboxing (objeto → primitivo) de forma automática.

PrimitivoWrapperMétodo útil
intIntegerInteger.parseInt("42")
doubleDoubleDouble.parseDouble("3.14")
booleanBooleanBoolean.parseBoolean("true")
charCharacterCharacter.isLetter('a')
longLongLong.parseLong("123456")
Genericos.java 
// Tipo genérico: <String> indica el tipo de elemento
List<String> nombres = new ArrayList<>(); // Diamond operator <>

// Autoboxing: int → Integer (automático)
List<Integer> numeros = new ArrayList<>();
numeros.add(10); // autoboxing
int n = numeros.get(0); // unboxing

// Conversión String ↔ primitivo
int    edad   = Integer.parseInt("25");
String edadSt = Integer.toString(25);

8.2 Interfaz List: ArrayList y LinkedList

Una List es una colección ordenada que permite duplicados y acceso por índice. Las dos implementaciones principales son ArrayList (acceso rápido por índice, lento para insertar/eliminar en el medio) y LinkedList (inserción/eliminación rápida en extremos, acceso por índice lento).

OperaciónArrayListLinkedList
Acceso por índice (get)O(1) – rápidoO(n) – lento
Insertar al final (add)O(1) amortizadoO(1)
Insertar en el medioO(n)O(1) si tienes el nodo
EliminarO(n)O(1) si tienes el nodo
Uso recomendadoLectura frecuenteInserción/eliminación frecuente
Listas.java 
import java.util.*;

List<String> lista = new ArrayList<>();
lista.add("Manzana");
lista.add("Banana");
lista.add(1, "Naranja"); // inserta en posición 1
lista.remove("Banana");
System.out.println(lista.get(0)); // Manzana
System.out.println(lista.size());   // 2
System.out.println(lista.contains("Naranja")); // true

// LinkedList: métodos adicionales para extremos
LinkedList<String> ll = new LinkedList<>();
ll.addFirst("Primero");
ll.addLast("Último");
System.out.println(ll.getFirst()); // Primero

// Recorrer con for-each
for (String s : lista) {
    System.out.println(s);
}

8.3 Interfaz Set: HashSet, LinkedHashSet, TreeSet

Un Set es una colección que no permite elementos duplicados. Existen tres implementaciones principales según el orden y el rendimiento requerido.

Implementación¿Ordena?Rendimiento¿Admite null?Uso ideal
HashSetNo (caótico)O(1) – el más rápidoSí (uno)Solo importa que no haya repetidos
LinkedHashSetPor orden de inserciónO(1)Sí (uno)Recordar orden de llegada
TreeSetOrden natural (Comparable)O(log n)NoLista siempre ordenada
Conjuntos.java 
// HashSet: sin orden garantizado
Set<String> hashSet = new HashSet<>();
hashSet.add("Java");
hashSet.add("Python");
hashSet.add("Java"); // duplicado ignorado
System.out.println(hashSet.size()); // 2

// LinkedHashSet: mantiene orden de inserción
Set<String> linked = new LinkedHashSet<>();
linked.add("C"); linked.add("A"); linked.add("B");
System.out.println(linked); // [C, A, B]

// TreeSet: orden natural ascendente
TreeSet<Integer> tree = new TreeSet<>();
tree.add(5); tree.add(1); tree.add(3);
System.out.println(tree);         // [1, 3, 5]
System.out.println(tree.first()); // 1
System.out.println(tree.last());  // 5

8.4 Interfaz Map: HashMap, LinkedHashMap, TreeMap

Un Map representa un diccionario de pares clave-valor. Las claves no se repiten. Los valores sí pueden repetirse. Se accede a un valor mediante su clave.

Mapas.java 
import java.util.*;

Map<String, String> mapa = new HashMap<>();
mapa.put("123", "Juan Pérez");
mapa.put("456", "Ana Gómez");
mapa.put("789", "Luis Rodríguez");

// Acceso por clave
System.out.println(mapa.get("123"));      // Juan Pérez
System.out.println(mapa.containsKey("456")); // true
mapa.remove("789");

// Recorrer con keySet()
for (String clave : mapa.keySet()) {
    System.out.println(clave + " → " + mapa.get(clave));
}

// Recorrer con entrySet() (más eficiente)
for (Map.Entry<String, String> e : mapa.entrySet()) {
    System.out.println(e.getKey() + " → " + e.getValue());
}

// TreeMap: claves ordenadas alfabéticamente
Map<String, Integer> notas = new TreeMap<>();
notas.put("Matemáticas", 9);
notas.put("Historia", 7);
System.out.println(notas); // {Historia=7, Matemáticas=9}

8.5 Iteradores (Iterator y ListIterator)

Un iterador es un objeto que permite recorrer una colección de forma segura, especialmente cuando se necesita eliminar elementos durante el recorrido (algo que no funciona bien con for-each). ListIterator permite además recorrer en ambas direcciones.

Iteradores.java 
List<String> lista = new ArrayList<>(
    List.of("Ana", "Borrar", "Carlos")
);

Iterator<String> it = lista.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.equals("Borrar")) {
        it.remove(); // eliminación segura
    }
}
System.out.println(lista); // [Ana, Carlos]

// ListIterator: recorrido bidireccional
ListIterator<String> lit = lista.listIterator(lista.size());
while (lit.hasPrevious()) {
    System.out.println(lit.previous()); // Carlos, Ana
}

8.6 Comparadores: Comparable y Comparator

Comparable (paquete java.lang) define el orden natural de una clase implementando el método compareTo(). Comparator (paquete java.util) define órdenes alternativos sin modificar la clase original, implementando el método compare().

Comparadores.java 
// Comparable: orden natural por nombre
public class Persona implements Comparable<Persona> {
    private String nombre;
    private int    edad;

    @Override
    public int compareTo(Persona otra) {
        return this.nombre.compareTo(otra.nombre); // orden alfabético
    }
}

// Comparator: orden alternativo por edad
public class ComparadorPorEdad implements Comparator<Persona> {
    @Override
    public int compare(Persona p1, Persona p2) {
        return Integer.compare(p1.getEdad(), p2.getEdad());
    }
}

// Uso con lambda (más conciso):
Comparator<Persona> porNombre = Comparator.comparing(Persona::getNombre);
Set<Persona> personas = new TreeSet<>(porNombre);
personas.add(new Persona("Fran", 18));
personas.add(new Persona("Ana",  19));
System.out.println(personas); // [Ana, Fran]

8.7 Clase de Utilidades Collections

La clase Collections (con 's') es diferente de la interfaz Collection. Contiene métodos estáticos de utilidad para operar sobre colecciones.

ColeccionesUtil.java 
import java.util.*;

List<String> nombres = new ArrayList<>(
    List.of("Lucía", "Carlos", "Ana", "Pedro")
);

Collections.sort(nombres);           // [Ana, Carlos, Lucía, Pedro]
Collections.reverse(nombres);        // [Pedro, Lucía, Carlos, Ana]
Collections.shuffle(nombres);        // orden aleatorio

List<Integer> notas = List.of(5, 7, 9, 4, 6);
System.out.println(Collections.max(notas)); // 9
System.out.println(Collections.min(notas)); // 4

List<String> palabras = List.of("sol", "luna", "sol");
System.out.println(Collections.frequency(palabras, "sol")); // 2

8.8 Objetos Inmutables

Un objeto inmutable es aquel cuyo contenido no puede cambiar una vez creado. Si se "modifica", en realidad se crea un nuevo objeto. Los ejemplos más conocidos en Java son String y los tipos envoltorio (Integer, etc.).

Inmutables.java 
String texto = "Hola";
texto.concat(" mundo");          // no modifica texto
System.out.println(texto);         // Hola

String nuevo = texto.concat(" mundo"); // crea nuevo objeto
System.out.println(nuevo);         // Hola mundo

// final en colección: no se puede reasignar la referencia
// pero SÍ modificar el contenido
final ArrayList<String> lista = new ArrayList<>();
lista.add("Hola");   // ✅ permitido
// lista = new ArrayList<>(); → ERROR de compilación

Entrada y Salida de Información (I/O)

En Java, la entrada y salida de datos se gestiona mediante flujos de datos (Streams), que son secuencias ordenadas de datos transmitidas en serie desde un origen hasta un destino. Esta abstracción permite usar el mismo mecanismo independientemente del dispositivo (pantalla, teclado, fichero, red, etc.).

9.1 Tipos de Flujos de Datos

CriterioTipoDescripción
SentidoEntrada (Input)Se LEE información desde el origen
SentidoSalida (Output)Se ESCRIBE información hacia el destino
AccesoSecuencialHay que pasar por los elementos anteriores para llegar al deseado
AccesoDirecto (aleatorio)Se accede directamente al elemento deseado
Tipo de datoCaracteresDatos codificados en caracteres (Unicode, ASCII)
Tipo de datoBytesDatos binarios sin codificación

9.2 Flujos Estándar: System.in, System.out, System.err

Mientras se ejecuta un programa, Java mantiene abiertos tres flujos predeterminados sin necesidad de crearlos manualmente.

FlujosEstandar.java 
// System.out → PrintStream (salida estándar: pantalla)
System.out.print("Sin salto de línea");
System.out.println("Con salto de línea");
System.out.printf("Formateado: %.2f%n", 3.14159); // 3.14

// System.err → PrintStream (salida de error: pantalla en rojo)
System.err.println("Error crítico detectado");

// System.in → InputStream (entrada estándar: teclado)
int byteLeido = System.in.read(); // lee un byte
System.out.write(byteLeido);      // escribe el byte
System.out.flush();               // vacía el buffer

9.3 Clase Scanner

Scanner añade una capa de abstracción sobre System.in que facilita la lectura de tipos primitivos y cadenas. Lee por tokens (grupos de caracteres separados por espacios por defecto).

MétodoQué leeEjemplo
next()Una sola palabra (hasta el primer espacio)String p = sc.next();
nextLine()Una frase entera (hasta Enter)String f = sc.nextLine();
nextInt()Un número enteroint n = sc.nextInt();
nextDouble()Un número decimaldouble d = sc.nextDouble();
hasNextInt()Comprueba si el siguiente token es intif (sc.hasNextInt()) { ... }
UsoScanner.java 
import java.util.Scanner;

public class HolaMundo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Introduce tu nombre completo: ");
        String nombre = sc.nextLine();

        System.out.print("Introduce tu edad: ");
        int edad = sc.nextInt();

        System.out.printf("Hola %s, tienes %d años.%n", nombre, edad);

        sc.close(); // buena práctica: cerrar el Scanner
    }
}

9.5 Ficheros y Directorios

La clase java.io.File representa un fichero o directorio en el sistema de archivos. No lo abre ni lo crea; solo lo representa y permite obtener información sobre él. Para crear, leer o escribir hay que usar las clases de flujos.

Ficheros.java 
import java.io.*;

// Clase File: representa el fichero
File archivo = new File("notas.txt");
if (archivo.exists()) {
    System.out.println("Ruta: " + archivo.getAbsolutePath());
    System.out.println("Tamaño: " + archivo.length() + " bytes");
} else {
    archivo.createNewFile(); // crea el fichero
}

// Escribir con FileWriter (caracteres)
try (FileWriter fw = new FileWriter("ejemplo.txt")) {
    fw.write("Hola desde Java\n");
    fw.write("Segunda línea\n");
} // try-with-resources: cierra automáticamente

// Leer con FileReader (carácter a carácter)
try (FileReader fr = new FileReader("ejemplo.txt")) {
    int c;
    while ((c = fr.read()) != -1) {
        System.out.print((char) c);
    }
} catch (IOException e) {
    e.printStackTrace();
}

// Escribir bytes con FileOutputStream
try (FileOutputStream fos = new FileOutputStream("datos.bin")) {
    byte[] datos = {72, 111, 108, 97}; // "Hola" en ASCII
    fos.write(datos);
}

9.6 Acceso Directo: RandomAccessFile

RandomAccessFile trata el fichero como un array de bytes gigante con un puntero de posición. Permite leer y escribir en cualquier posición del fichero sin recorrerlo secuencialmente.

AccesoDirecto.java 
import java.io.*;

// "rw" → lectura y escritura
try (RandomAccessFile raf = new RandomAccessFile("datos.txt", "rw")) {
    raf.writeBytes("Hola Mundo");

    // Mover puntero a posición 5 ('M') y sobreescribir
    raf.seek(5);
    raf.writeBytes("P");

    // Volver al principio y leer
    raf.seek(0);
    System.out.println(raf.readLine()); // Hola Pundo
    System.out.println("Tamaño: " + raf.length());
}

9.7 Serialización

La serialización es el proceso de convertir un objeto en una secuencia de bytes para almacenarlo o transmitirlo. La deserialización es el proceso inverso. Para que un objeto sea serializable, su clase debe implementar la interfaz marcadora Serializable.

ConceptoDescripción
SerializableInterfaz marcadora (sin métodos). Indica que la clase puede serializarse.
serialVersionUIDID único estático que garantiza compatibilidad entre versiones de la clase.
transientModificador que excluye un atributo de la serialización (p. ej., contraseñas).
ObjectOutputStreamEscribe objetos en un flujo (serializa) con writeObject().
ObjectInputStreamLee objetos de un flujo (deserializa) con readObject().
Serializacion.java 
import java.io.*;

// Clase serializable
public class Jugador implements Serializable {
    private static final long serialVersionUID = 1L;
    private String nombre;
    private int    nivel;
    private transient String password; // NO se serializa

    public Jugador(String nombre, int nivel, String password) {
        this.nombre   = nombre;
        this.nivel    = nivel;
        this.password = password;
    }
}

// Serializar (guardar)
Jugador j = new Jugador("Fran", 42, "s3cr3t");
try (ObjectOutputStream oos = new ObjectOutputStream(
        new FileOutputStream("jugador.dat"))) {
    oos.writeObject(j);
}

// Deserializar (recuperar)
try (ObjectInputStream ois = new ObjectInputStream(
        new FileInputStream("jugador.dat"))) {
    Jugador recuperado = (Jugador) ois.readObject();
    // recuperado.password → null (era transient)
}

9.8 XML en Java: API DOM

XML (eXtensible Markup Language) es un lenguaje de marcado independiente de plataforma para estructurar datos. El modelo DOM (Document Object Model) carga todo el XML en memoria como un árbol de nodos, permitiendo leer y modificar su contenido. La API DOM está incluida en el JDK en el paquete org.w3c.dom.

Interfaz DOMQué representa
DocumentTodo el documento XML (raíz del árbol)
ElementUn elemento delimitado por etiquetas (<tag>...</tag>)
NodeCualquier objeto del XML (texto, tag, atributo...)
NodeListLista de nodos
AttrAtributo de un elemento
TextContenido textual de un nodo
LecturaXML.java 
import javax.xml.parsers.*;
import org.w3c.dom.*;

// Leer XML
DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
DocumentBuilder        builder = factory.newDocumentBuilder();
Document               doc     = builder.parse(new File("datos.xml"));

Element  raiz     = doc.getDocumentElement();
NodeList personas = doc.getElementsByTagName("persona");

for (int i = 0; i < personas.getLength(); i++) {
    Element persona = (Element) personas.item(i);
    String  nombre  = persona.getElementsByTagName("nombre")
                              .item(0).getTextContent();
    System.out.println("Nombre: " + nombre);
}

// Escribir XML
Element nuevaPersona = doc.createElement("persona");
Element nombreElem   = doc.createElement("nombre");
nombreElem.appendChild(doc.createTextNode("Lucía"));
nuevaPersona.appendChild(nombreElem);
raiz.appendChild(nuevaPersona);
